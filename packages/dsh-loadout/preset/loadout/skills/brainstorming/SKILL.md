# Brainstorming

1. Read relevant code, tests, docs, and recent changes. Identify the intended outcome and the open choices that could affect it.
2. Make reversible implementation choices. Ask one focused question at a time for decisions the user owns.
3. Recommend the smallest workable design. Compare alternatives by trade-offs that affect the outcome. When originality matters, explore distinct core ideas and compare them with the brief and available references.
4. Scale the plan to the change. For substantial work, cover scope, components, data flow, edge cases, and verification. Follow repository patterns and keep each change focused.
5. Deliver the requested plan or critique. For implementation, proceed once material choices are resolved and any required approval is in place.
